# 学习平台界面与交互验证

2026-10-28；macOS arm64、本地 Moodle 5.3+，仅模拟账号和数据。用户可见名称为“学习平台”，技术来源与第三方许可继续保留。此次没有修改原React/Node业务源码、共享契约或生产环境。

## 实际执行

- `python3 moodle-sample/scripts/sample.py verify`：题型11/11、HTTP25/25，数据库检查通过。检查包含登录名称、已提交状态、有效输入在非法答案错误时保留、版本冲突409、CSRF、学生与教师跨班隔离、CSV导出及实际作业提交。可复现结果见本目录schema.json、http.json、database.json。
- 本机内嵌浏览器实际登录模拟学生和教师：登录页、任务中心、画像、教师报告及原生作业页面可打开，页面名称为学习平台，已检查页面可见文字没有Moodle字样。未声称检查站点全部管理员页面或所有语言包。
- 课程搜索无匹配时显示0/2和清除筛选；批次筛选显示1/2。学生填写第18题时进度3/7变4/7、状态变为未保存；撤销后恢复3/7和已保存；编辑第2题并保存后服务端返回已保存，教师报告可读到模拟文本。
- 教师报告按学号搜索，未匹配显示空状态；输入001001显示1/1；展开/收起可用，查看了当前班级模拟画像。搜索不改变CSV导出的数据范围，界面有提示。
- 1280px桌面登录、学生任务中心和画像、教师报告截图；375px画像、量表、教师报告及原生作业页面实际浏览。375px的画像、教师任务中心、教师报告、原生作业测得document.scrollWidth均为375。浏览器视口模拟不是移动设备验收。
- 教师报告及学生画像页面读取浏览器警告/错误日志为空；PHP及Python语法检查、`node --check`、`git diff --check`通过。

## 发现与修复

教师进入原生作业页面后，系统额外创建一条教师的新建状态作业记录。数据库验证脚本之前把assignment作为查询首列，框架据首列索引结果，造成同作业多条记录相互覆盖；这使旧断言误报没有已提交答卷。已改用唯一记录id作为首列并重跑：实际有学生submitted记录，数字成绩0。没有删除或改写数据来通过测试。

校验错误时此前会丢弃其他有效输入；现在保留可单独验证的输入并提示本次未保存。冲突继续保留本页输入和旧版本，提供新标签查看已保存草稿；没有实现自动合并或自动保存。

## 边界

画像进度仅代表七道已配置题是否有填写，不代表题目完成度或成绩；11道题仍待教学方确认类型。离开未保存页面的浏览器提醒已实现，尚未在各移动浏览器或真机逐一验证。教师查询对本课程已加载的草稿进行本页筛选，尚未验证大班性能。实际公网、正式评价、生产隐私与备份、300/500人并发和真实设备未测试。

启动器与本机可访问地址见../README.md。产品显示名称不改变Moodle、PHP、PostgreSQL及素材的来源和适用许可；样板仍仅限模拟数据。
