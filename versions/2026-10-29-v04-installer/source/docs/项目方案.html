先把一条教学流程

老师发布课前问题，学生在线作答，系统根据评价标准生成反馈。本机 Codex 负责后台与集成，同事 Codex 负责前端，通过 GitHub 分支和合并请求协作。

建设方式
采用适配手机和电脑的联网网页，共用一套云端后台和数据库。学校无需提供服务器，由项目自行购买托管云服务。

当前状态
本文件用于讨论方案。当前源码已完成本地 HTTP 集成，正式评分、云部署、300 人压测和真机验收仍待完成；最新状态以仓库 README 和接续文件为准。

第一版做什么

第一版重点是稳定完成教学流程。以文字题目、文字回答、基础图表和教师复核为范围，界面清楚、手机可用即可。

  1. 教师发布选择班级、题目及截止时间
  2. 学生作答账号登录、保存草稿
  3. 保存提交云端留存并返回回执
  4. 系统评价规则评分或 AI 辅助评价
  5. 查看与复核个人报告、班级汇总

纳入首版

  • 教师、学生两类账号及班级关系。
  • 发布问题、截止时间、草稿和提交记录。
  • 可配置的评价规则与评分任务。
  • 个人维度图表、文字建议、教师复核。
  • 班级提交情况和结果导出。
  • 基础权限、备份及异常记录。

后续按需扩展

  • 音视频、拍照识别和复杂附件。
  • 微信小程序、学校统一身份认证。
  • 复杂题库、考试监考、社交互动。
  • 精细视觉设计和高级学习画像。

题目与评价体系尚待提供。雷达图需有清晰、可比较的维度；单项指标可先用条形图。

两位开发者，按模块分工

建议由 Codex 统一集成，同事 Codex 开发界面，你把握教学要求和最终验收。两套工具先按同一份数据约定开发，减少互相覆盖和反复返工。

Codex：后台与统一集成

  • 确定项目结构、数据字段、接口及模块边界。
  • 实现账号权限、班级、发布、提交与云数据库。
  • 实现评分任务队列、规则版本、模型调用和教师复核。
  • 接入 同事 Codex 交付的页面，处理数据和状态。
  • 完成关键验证、集中提交压测、部署和备份恢复说明。

交付：数据与接口约定、后台模块、集成版本、测试记录和部署说明。

同事 Codex：页面与图表

  • 按约定开发教师发布页、班级概览和评分复核页。
  • 开发学生任务列表、文字答题和个人报告页。
  • 完成手机、电脑布局及雷达图或条形图展示。
  • 先使用标明为演示的数据，实现加载、空白、失败等状态。
  • 通过统一的数据访问层调用接口，交付给 Codex 集成。

交付：前端页面、图表组件、演示数据、界面状态清单；不自行更改后台字段或接入真实密钥。

你：项目负责人和教学验收人

  • 提供题目、参考答案、评价维度、分值及教师评分样本。
  • 决定首版范围、评价结果对谁可见、何时允许教师修订。
  • 开通并管理云账号、域名、付费账号，确认报销和上线主体。
  • 在两个工具之间交接任务和版本，组织老师、学生小范围试用。
  • 使用真实 Windows、Android、MagicOS、iOS 设备验收并反馈。

交付：确认的需求与评分标准、可用账号、小样本试用反馈、最终验收意见。

可复制各角色任务说明，再由你交给对应工具；本页未连接两个开发工具。

怎样减少两套工具协作时的返工？

先固定一份《数据与接口约定》，包括题目、答卷、维度分数、评价规则版本，以及“草稿／已提交／待评分／已评分／评分失败”的状态含义。界面端只使用约定的字段。

两套工具分别在独立分支或目录中工作，不同时编辑同一文件。每次交接包含：修改文件、使用方法、已做验证、已知问题。由 Codex 审查并合并到主版本；变更字段时同步更新页面与演示数据。

AI 开发工具与正式系统中的 AI 评分有什么区别？

Codex 和 同事 Codex 用来协助你写代码。上线后的自动评分，需要系统后台单独调用模型 API，并单独计费；开发工具的订阅不等于学生评分的调用额度。模型供应商和版本在样本评估后确定。

15–23 个工作日60–90 小时 ÷ 每天投入

300 人集中提交：先收答卷，再排队评分

学生提交后，后台先可靠保存答案并返回成功回执，再分批调用评分模型。关闭页面后，评分任务仍在云端继续执行，学生之后可以回来查看。

“已提交”必须以云端保存成功为准。实现重复提交防护、任务重试和失败记录；控制评分并发，避免集中调用超过模型额度。300 人支持能力须通过正式环境压测验证。

账号、数据与上线安排

首版可采用分配账号与初始密码、首次登录改密、班级加入码，避免依赖学校统一登录。学生访问自己的答卷，教师按班级查看；权限由后台执行。

AI 调用密钥保存在云端，评分时尽量使用匿名答案。云账号、域名、部署地区及备案可行性在小样例阶段核实；开发阶段可先验证测试入口，正式教学使用前确认稳定网址和上线条件。

运行一年期间设置费用与错误提醒、定期导出和备份；实际做一次恢复验证。项目结束前导出数据并决定续费、迁移或停止服务。维护时间另行预留，不包含在初版 60–90 小时内。

用实际结果验收初版

界面朴素可以接受，数据保存、访问权限和评价可追溯需要从首版做好。以下均为待验证项。

  • 跨设备完成一轮教学流程

    教师在电脑发布，学生在手机作答，双方按权限看到云端结果。

  • 300 个独立账号集中提交测试

    核对提交记录完整性、失败重试和重复防护；页面请求和评分队列都需记录结果。

  • 评分与教师判断对照

    使用真实答案样本；保留规则版本、模型版本、得分依据和人工修订记录。

  • 代表性设备和数据恢复测试

    实际检查 Windows、Android、MagicOS、iOS；验证越权访问被阻止、备份能恢复、数据能导出。

开工前由你补充

一组真实课前问题、参考答案、评价维度和评分样本；确认结果可见范围，以及全年预计学生总数和作业次数。

首个开发里程碑

只用一道题，让两个设备完成“发布 → 提交 → 固定规则评分 → 查看结果”。先验证联网基础，再接入正式评价体系。
