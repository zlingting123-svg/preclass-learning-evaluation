# 原系统与 Moodle 的最小映射

基于 `backend/oss-foundations@4e15d02` / shared v0.2.0；这不是接口兼容声明。

| 原需求/机制 | 本样板的 Moodle 对应 | 本轮范围 |
|---|---|---|
| 学号字符串与账号 | user.username、idnumber | 四位模拟学生，001001等保留前导零 |
| 跨期复用账号 | 同一user参加不同课程 | 001001同时参加秋季A与下一春季课程 |
| cohorts/教学批次 | course category | 2026秋季跨至2027年1月、2027春季对照 |
| 班级与教师授权 | 每班一个course，课程级角色/能力 | 两班两教师；不授予全站管理角色 |
| 名单CSV预览/指纹确认 | 四行fixture校验+指纹+Moodle用户/选课API | 不是500人产品导入UI，不移植Node CLI或双写SQLite |
| 四次作业 | 原生 mod_assign | 两班各发布第1次，其他只显示计划 |
| 草稿与正式文字提交 | 原生 assignsubmission_onlinetext | 本机实际保存与提交；不自建作业状态机 |
| 18题混合画像 | local_preclass_sample | 七题可选填草稿，十一题待确认，未开放正式提交 |
| 草稿版本冲突 | 自定义表version+Moodle Lock API+事务 | 锁内重新读取，版本不符409 |
| 教师仅看本班 | course context权限+查询courseid | 画像、CSV、原生作业越权均实际测试 |
| 报告与导出 | 本班画像原始内容+CSV | 不生成总体学习结论、雷达分或能力评分 |
| 正式Scorer/AI/复核 | 未接入 | 原Node实现保留；Moodle样板不伪造评分 |

## 结构选择

学生任务中心仅列已选课且在样板白名单的课程。Moodle本身承担认证和原生作业提交，插件只补画像与入口。暂时不连接原Node后台，不让两套账号和两套数据库同时成为教学数据主库。

教师使用课程级 editingteacher，禁止该课程角色 accessallgroups。真正的数据边界仍然是独立课程与服务端能力检查；分组仅辅助组织。要把七位教师放入同一大课程，需要重新设计权限，并重新检查原生作业、成绩簿、成员列表、报告和导出，不能沿用当前结论。

## 接续建议

先通过样板确认是否采用 Moodle 主系统及“每班独立课程”的管理方式。接着确认11题题型、量表锚点、必填/正式提交规则和真实评分细则；再完成生产账号生命周期、受控名单导入UI、插件隐私导出/删除、保留期限与备份恢复、问卷正式提交和审计。

插件当前没有 privacy provider，也未实现 Moodle 课程备份/恢复API、插件卸载数据保留策略或真实数据删除流程，仅适用于本地模拟。不要使用真实学生数据进行教学。正式部署还需升级运行时、评估500人/7教师规模，并完成真实设备、并发及运维验证。

仓库React/Node路线与Moodle路线如何取舍尚未定案。本次只交付可比较的Moodle最小闭环，未迁移既有学生数据、替换原系统或合并依赖PR。
