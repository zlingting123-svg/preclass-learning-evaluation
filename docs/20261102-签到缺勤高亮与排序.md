# 签到缺勤高亮与导出排序

2026-11-02，当前云端 20261102-attendance-export，上版 20261102-teacher-grade。

单场Excel未签到人员整行红色高亮。多场汇总标红具体未签到场次，同时标红该学生姓名、学号及累计未签到次数；正常签到及位置异常仍按各自状态呈现，不把有缺勤者的所有场次都标成缺勤。

增加“未签到名单”工作表，列出姓名、学号、未签到次数和对应场次；增加“签到概况”，汇总场次、人数、未签到人次与排序方式。保留原单场/汇总主表及定位核对说明。“不在当次名单”不计缺勤；未结束的单场只显示待签到，不计入未签到名单。未签到不等于确认缺席，结合请假或补签核对。

签到记录上方增加“导出排序”：默认导入名单顺序，可选学号升序、姓名拼音、未签到优先。单场、班级累计及自行勾选场次使用同一选项。未签到优先按所选场次未签到次数降序，同次数保留名单顺序。

旧版成员读取按UUID排序、累计导出固定按学号，无法体现导入先后。本次新增 class_roster_order 元数据，并在管理员批量、受控本地、旧问卷名单导入三条现有流程的原事务内保存学生ID顺序，不改变账号或成员规则。再次导入以本次名单优先，未包含旧成员接在后面。现有旧名单没有此元数据，按SQLite成员首次入库顺序恢复；已移除且没有顺序记录的历史成员在末尾按场次快照保留。因此旧名单被人工删除重建过时，无法保证恢复最初原文件顺序。

本次不修改历史签到快照、定位或已保存成员。顺序元数据在之后实际导入时才写入，未批量改写生产数据。

验证：独立内存数据库验证成员入库顺序、显式导入顺序、四种排序、未签到名单、计数、不在名单不缺勤、进行中不缺勤、角色和班级权限、历史快照不变。旧场次选择/点名删除回归通过。用openpyxl读取生成的合成单场/汇总XLSX，核对状态、姓名、缺勤次数和未签到名单的红色填充。浏览器隔离及正式资源验证默认排序、单场/累计/选择场次参数及下载，320/375/414/768宽度无横向溢出。没有使用真实学生数据进行导出测试。
