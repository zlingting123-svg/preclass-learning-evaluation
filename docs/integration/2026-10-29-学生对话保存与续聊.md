# 学生对话保存、删除与续聊

本轮在feature/student-conversations上接续服务管理端5984bc6。用户明确要求学生会话可以删除、下次打开能够恢复并继续追问；此要求替代此前全局“不留存具体对话”的约束。教师仍只看聚合方向，服务管理端不开放学生对话正文。

## 实现

- Conversations服务将线程、轮次、消息、来源及中断状态写入主系统私有SQLite，按账号与课程/班级隔离；用量账本仍只存计费元数据。
- 记录每门课选中的会话及上次聊天课程。重新登录进入AI助手时，恢复原课程和会话；原主业务路由也支持登录后回到原助手页面。
- 两处学生页面均调用同一持久会话Hook：已有商业预览保留外观，新增历史列表、删除、删除确认、刷新历史；原主页面也支持新建/切换/删除/恢复。
- 对话删除会移除在线线程、消息和选中记录；若仍在生成则取消请求，迟到回调不能重建记录。历史用量和未知费用记录保留；既有备份、WAL及存储介质不属于本次逻辑删除验证，不声称取证级安全擦除。
- 重复clientRequestId不会重新生成。生成中断或进程重启后，未完成轮次标为interrupted，不自动产生付费重试；失败消息保留供用户查看或重新填写。
- 每个学生在每门课最多100条线程、每线程100轮。传给模型的上下文最多近期3个完整成功轮次、3500字节，并受整体输入预算进一步裁剪。失败/拒答轮次不作上下文。
- 上下文是非权威数据，回答仍须当前授权资料支持。当前是词项检索基线，提供有限、严格匹配的指代续问（如“它有什么作用？”），不是通用语义检索或完整语言理解。真实DeepSeek仍关闭。

## API

所有接口前缀`/api/v1/core/ai`，复用已有Bearer会话及当前课程权限，只允许student：

| 方法与路径 | 内容 |
|---|---|
| GET /threads?classId=… | 本人该课程线程列表和activeId |
| POST /threads | `{classId}`，服务器生成owner和线程ID |
| GET /threads/:id | 本人线程消息、来源和状态 |
| POST /threads/:id/select | `{}`，持久保存当前选择 |
| DELETE /threads/:id | 删除在线线程和消息，保留用量 |
| POST /threads/:id/questions | `{question,clientRequestId}`，POST SSE，服务端读取可信历史 |
| GET /last-context | 本人仍有权限的最近课程/线程 |

旧`/chat`和`/chat/stream`继续作为单次请求兼容接口；不能用它们替代本轮持久线程接口。客户端不能提交owner、任意历史角色或其他班级上下文。公共DTO在shared/conversations.ts。
