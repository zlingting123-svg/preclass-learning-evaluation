## 未完成或尚未验收

1. 正式公网域名、备案/HTTPS、跨真实设备外网访问。现有服务器是SSH隧道私有调试，不是可直接发给学生的公网教学网址。
2. 正式课程检索校准与真实资料样本评估；当前retrievalCalibrated=false，不把私有开发豁免写成正式生产就绪。
3. 问卷AI生成、教师AI统计评价和系统AI管理仍为预留功能，需要单独确认交付范围；聊天可用不代表三处均已实现。
4. 实际Android/MagicOS/iOS真机与校园网络验收；浏览器宽度模拟只证明布局。
5. 真实整站300人集中提交、500人课程规模与真实提供商限流/成本验收。AI测试中的300/500为模拟上游或连接结构，不等于整站容量。
6. 生产完整备份计划、受控异机副本与恢复演练；既有单库备份和模拟恢复不能代替整套生产验证。
7. 真实复杂PDF/Office、OCR/搜索及课程资料可用性按实际文件单独验收，不从解析样例外推。
8. 本次0.3没有重新制作或发布Ubuntu安装器；旧installer-v04及其源码哈希继续指向旧版本，不应冒充包含本次更新。

## 用户确认的下一阶段顺序（2026-10-30）

以下顺序覆盖此前泛化的“下一步”建议，产品版本仍为0.3；本次仅更新任务安排，不代表功能已经实现，也不启动采购、开放公网或压测。

### 第一阶段：AI解读问卷情况——下一项开发

- 接通教师端现有`/core/ai/insights`预留接口，按教师获授权的班级和问卷读取已提交答卷统计。
- 后台计算人数、有效作答人数、比例与完成情况；向模型提供匿名汇总数据，生成回答分布摘要、值得关注的现象与教学建议，不让模型编造数值或给兴趣/偏好题判对错。
- 明确多选题、选填题、零作答及当前名单/累计答卷口径；没有资料库时，不假称已引用课程资料，不强行输出有来源的学科结论。
- 接入已有用途路由、Key管理及用量门禁；处理重复点击、失败、超时和费用状态，教师可查看并复核解读结果。
- 验收：授权与跨班隔离、输入确为匿名统计、数字与图表一致、零数据提示、失败可见；先隔离测试，再验证已配置的真实模型路径。
- AI自动生成问卷属于另一个预留功能，本次不因“AI解读”任务自动扩大到问卷生成。

### 第二阶段：等待用户上传资料库——收到资料后再推进

- 第一阶段完成后等待用户上传资料，不擅自搜集或用模拟资料代替正式课程资料库。
- 收到资料后核对文件、解析结果、课程/班级归属与发布范围，再完成检索、来源引用和回答质量校准。
- 未收到资料或尚未通过样本校验时，保留“未校准”的实际状态，不把真实聊天可用写成资料库校准完成。

### 第三阶段：购买域名并进行压力测试——最后实施

- 待前两阶段完成、用户确定具体域名及购买信息后，再办理域名、解析、正式HTTPS和访问入口。
- 在正式环境准备好后进行整站压力测试，覆盖登录、问卷读取与提交、统计读取及AI排队/限流，记录完成数、错误率、延迟、服务器资源和模型调用费用。
- 区分模拟上游负载与真实提供商测试；300人集中提交及500人课程规模需按实际场景验收，不沿用旧连接测试作容量结论。
- 域名/公网与压测前检查备份和恢复条件；这属于第三阶段验收准备，不改变上述用户指定顺序。

完成一个阶段后更新任务书和接续。第二阶段以用户实际上传资料为启动条件；第三阶段不提前执行。
